# studio-ochen-construct

Локальный редактор собирает иллюстрации из предоставленных векторных предметов. Gemini выбирает смысловые группы, три положения и окружение; приложение размещает исходные SVG и сохраняет редактируемый вектор.

Десять предметов в авторских S/L, три формата холста, три варианта композиции, слои, ручное редактирование и экспорт SVG/JSON. Контуры и масштаб исходников сохраняются.

## Быстрый запуск

Node.js 22+, Python 3 для подготовки статической публикации:

```sh
npm ci
npm start
```

Редактор: http://localhost:8000/. Для живой генерации скопируйте `.env.example` в `.env` и заполните параметры собственного защищённого прокси. Для работы вручную и «По словам» ключи не требуются.

## GitHub Pages

```sh
npm run build:pages
npm run check:pages
npm run preview:pages
```

Предпросмотр: http://localhost:8001/. Сборка `_site` содержит редактор и все три галереи (234 SVG). Подбор «По словам», слои, импорт JSON и экспорт работают в браузере. Gemini подключается к отдельному HTTPS gateway, адрес которого задан в deployment/pages.json; токены остаются на сервере. Сохранённые результаты доступны из меню «Проект».

Workflow `.github/workflows/pages.yml` выполняет проверки и публикует `_site` при push в main. В GitHub нужно выбрать Settings → Pages → Source: GitHub Actions. [Порядок публикации и подключение своего домена](docs/pages-delivery.md). [Репозиторий на GitHub](https://github.com/SavDen/StudioOchenConstruct). Адрес Pages добавим после подтверждённой публикации.

## Проверка перед отправкой

```sh
npm test
npm run check:secrets
npm run build:pages
npm run check:pages
```

Все 137 тестов используют сохранённые ответы или mock API и не расходуют квоту Gemini. Проверка секретов просматривает файлы для Git и содержимое отчётных ZIP; `python3 scripts/check_secrets.py --history` дополнительно проверяет историю. Локальные env, upstream-ответы, резервные архивы и промежуточная диагностика исключены из Git. Минимальные тестовые данные находятся в tests/fixtures.

## Запуск

Нужен Node.js 22 или новее:

```sh
npm start
```

Откройте http://localhost:8000/. Статический редактор и подбор «По словам» работают без Gemini через `npm run start:static`. Для Gemini используйте `npm start` и заполните `.env` по `.env.example` либо соседний `.env.proxy`: HTTPS-адрес существующего прокси, его токен и модель. Ключи остаются на серверной стороне. Изменение env требует перезапуска.

## Как пользоваться

Введите тему или названия предметов. При необходимости заполните «Пожелания к окружению» в настройках. Один запрос Gemini создаёт планы сразу для трёх форматов: квадрат 1000×1000, горизонтальный 1200×630 и вертикальный 800×1200. В каждом — три варианта расположения одного набора, всего девять сохранённых сцен. Для «Любит писать» книга и ручка могут быть двумя главными предметами: ручка на странице, рядом и поперёк книги.

S и L заменяют весь набор предметов и окружения реальными исходниками. Переключение не вызывает ИИ и не пересобирает окружение: позиции согласованно переходят между размерами, сохраняются связи с опорами, повороты, отражения и ручные правки. Масштаб каждого SVG зафиксирован 1:1; ползунка увеличения нет. Размер холста остаётся прежним. Дополнительные размеры доступны в «Размеры холста»: 1920×1080, собственные размеры от 256 до 4096 и базовый квадрат S 500×500 или L 1000×1000. Предметы могут выходить за края кадра; большой набор невозможно одновременно вписать целиком и сохранить исходные размеры.

«Собранно» собирает связанную группу, «Со смещением» меняет взаимное расположение предметов, «Под заголовок» оставляет левые 43% под текст. Функциональная пара чтения располагает лампу слева от книги. В коллекции независимых образов лампа может находиться справа. Фоновые предметы могут быть крупными монохромными фрагментами у края, а не обязательно целыми миниатюрами.

«Обновить окружение» меняет фон только текущего варианта. Главная группа сохраняет координаты, повороты, отражения, видимость, порядок, акцент, камеру и размер. Например, можно заменить фрагмент лампы цветами или написать «без фоновых предметов». Общий флажок видимости не запрещает модели выбирать фон; он управляет показом и экспортом уже выбранных объектов.

Кнопка «Пересобрать · N / 3» переключает три сохранённых варианта текущего формата без нового запроса к Gemini. У каждой пары «формат + вариант» свои предметы, слои, S/L, палитра, кадр и пожелания к окружению. Кнопки форматов восстанавливают сохранённую сцену. JSON проекта версии 2 включает все девять сцен и дополнительные размеры, если они использовались. Старые проекты автоматически переносятся, включая варианты с разными форматами. Отмена и повтор учитывают переключения и память.

После ручного перемещения, поворота или отражения расстановка текущего варианта переносится во все подготовленные форматы. Между предметами сохраняются расстояния, а группа привязывается к центру рамки с учётом камеры; масштаб SVG не меняется. Варианты 1, 2 и 3 остаются независимыми. Новый дополнительный формат после ручной правки также получает сохранённую расстановку. Ручная ширина/высота и кнопка «Холст под набор» меняют только рамку, сохраняя точные координаты и камеру. Обновление окружения, палитры и переключение S/L сами по себе не запускают такую синхронизацию. Флаг ручной расстановки хранится в JSON-памяти.

Предметы можно добавлять из библиотеки, перемещать, вращать, отражать, дублировать, удалять, скрывать и менять местами в слоях. При скрытии единственного видимого главного следующий видимый слой становится главным. Escape и клик по пустоте возвращают вкладку «Композиция». Изменение акцента/кадрирования перемещает камеру без zoom. SVG экспортируется отдельными векторными группами, а не растром.

## Библиотека и архитектура

- `library/sources/canonical/` — неизменённые отдельные SVG из VectorTestov и их SHA-256.
- `library/manifest.json` — 10 предметов × S/L = 20 элементов, с цветной и монохромной презентациями (40 файлов), исходными размерами и происхождением.
- `library/assets/` — те же пути и viewBox, дополненные атрибутами цветовых слотов. Три исходные палитры находятся в `library/palettes.json`.
- `dist/data.js` — подготовленная библиотека для офлайн-редактора.
- `dist/reference-layout.js` — новая сборка в исходном масштабе, смысловые группы, опоры, позиции, обрезка и размещение окружения.
- `dist/engine.js` — проверка проекта, векторный рендеринг, слои, ручные операции; прежний алгоритм сохранён для совместимости старых проектов.
- `dist/composition-view.js` — камера без увеличения, смена S/L, три формата × три варианта и независимая память снимков.
- `dist/ai-plan.js` — схема ответа, проверка известных предметов/ссылок/циклов/отрицаний и защита главной группы в режиме окружения.
- `prompts/composition-system.txt` — русскоязычный промпт с разделением главной группы, окружения и функциональных связей.
- `scripts/serve.mjs` — локальный HTTP-сервер и gateway к защищённому HTTPS API Gemini. Новый `mode=environment` использует тот же `/api/compose` и возвращает только обновлённую сцену текущего варианта.

Переподготовка библиотеки:

```sh
python3 scripts/import_vector_library.py /путь/к/VectorTestov
npm run build
node scripts/build_geometry.mjs
```

В этой рабочей папке `illustration-library` служит исходной подготовленной библиотекой и копируется при build. В отдельном архиве без неё используется собственная `library`. Для графической проверки/пересборки геометрии нужен dev-пакет sharp (`npm install`); рабочему редактору зависимости не требуются.

## Совместимость и проверки

Старые JSON поддерживаются. При загрузке в редактор снимаются прежний масштаб и zoom, сохраняются позиции/трансформации и все три снимка. Исходный browser autosave перед первой миграцией сохраняется под ключом `svg-composition-studio-v1-before-native`. Внешний вид старого проекта меняется из-за возврата к исходным размерам; новые композиции используют новую сборку. Новые шаблоны раскладки изолированы от старых и сохраняют точные координаты.

`npm test` проверяет исходные контуры и размеры, S/L, три схемы ручки, функциональную пару/коллекцию, разделение композиционных режимов, камеру 1:1, отрицания, безопасный API, неизменность главной группы при обновлении окружения и память JSON. Исторические тесты отдельно проверяют совместимость прежнего движка. Просматриваемые результаты находятся в exports, примеры — в qa/examples. Промежуточные локальные скриншоты и резервные архивы в репозиторий не входят.

Gemini получает два PNG-листа реальных ассетов выбранного размера: главные и монохромные фоновые. Они подготовлены из исходных SVG в `library/vision`; для обновления используется `npm run build:vision` (нужен `sharp`). `npm start` подключает каталог автоматически и отправляет изображения через уже существующий нативный маршрут HTTPS-прокси, без изменения удалённого сервера.

Визуальный ответ содержит `staging`: три формата, по три плана размещения каждого предмета. `canvas` задаёт нормализованный оптический центр в кадре, `on` — точку на конкретной опоре, `left/right/above/below` — отдельное положение относительно соседа. Исполнитель `dist/staging-plan.js` сохраняет масштаб 1:1, проверяет опоры, устраняет недопустимые пересечения и сообщает о коррекциях. Старые проекты без `stagingPlans` используют совместимую прежнюю сборку. Смена S/L сохраняет набор предметов и проверяет новую геометрию, без обращения к модели.

У сложной вложенной схемы девяти планов Google отклонил constrained decoding. Поэтому визуальный режим использует JSON output с полной схемой в текстовом контексте и строгой проверкой на локальном сервере. Недопустимая опора заменяется размещением рядом с явным замечанием; неизвестные предметы, циклы, произвольный масштаб и неполные планы отклоняются.

`node scripts/test_metaphors.mjs` выполняет проверочный набор метафор и сохраняет каждый SVG и JSON-проект в `exports/metaphors-2026-11-04`. `node scripts/build_metaphor_gallery.mjs` создаёт автономную галерею; сервер открывает её по `/reviews/metaphors-2026-11-04/`. Учтите: повторный тест использует квоту Gemini; готовые результаты автоматически пропускаются.

Ручной редактор допускает свободное расположение. Новая сборка использует библиотечную художественную грамматику, а не универсальную физическую симуляцию. Перекрытия на опорах и обрезка краями допустимы. Точное повторение всех старых примеров с авторским уменьшением предметов не обещается: приоритет нового режима — заданный пользователем запрет масштабирования.

Работа с пользовательской палитрой отложена по запросу пользователя. Сейчас доступны три исходные схемы.
